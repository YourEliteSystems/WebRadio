# UI Integration

The WebRadio Plugin SDK allows plugins to extend the application's user interface.

Plugins can contribute pages, settings, dialogs, toolbar actions and other interface elements while remaining fully independent from the WebRadio Core.

The goal of the UI API is to provide a consistent user experience across both built-in features and third-party plugins.

---

# Overview

The UI API enables plugins to integrate seamlessly into the application.

Typical UI extensions include:

* Sidebar pages
* Settings pages
* Dialog windows
* Toolbar actions
* Status bar items
* Context menu entries
* Notifications

Future versions may introduce additional UI extension points.

---

# UI Architecture

```text
WebRadio UI

├── Core Pages
│
├── Plugin Pages
│
├── Plugin Settings
│
├── Plugin Dialogs
│
└── Plugin Components
```

Plugins become part of the application without modifying the core interface.

---

# Sidebar Pages

Plugins may register their own pages inside the application's sidebar.

Example:

```javascript
context.ui.registerPage({

    id: "discord",

    title: "Discord",

    icon: "discord",

    component: "./pages/Discord.jsx"

});
```

Once registered, the page becomes available through the navigation sidebar.

---

# Settings Pages

Plugins may expose configuration pages through the application's settings window.

Example:

```javascript
context.ui.registerSettings({

    id: "discord",

    title: "Discord",

    component: "./settings/DiscordSettings.jsx"

});
```

This allows users to configure plugins without leaving WebRadio.

---

# Dialogs

Plugins may open their own dialogs when user interaction is required.

Typical examples include:

* Login dialogs
* Confirmation dialogs
* Import and export wizards
* Configuration assistants

Dialogs should follow the same visual style as the rest of the application.

---

# Toolbar Actions

Plugins may contribute actions to the application's toolbar.

Examples include:

* Refresh
* Connect
* Synchronize
* Scan
* Open Dashboard

Toolbar buttons should represent frequently used actions.

---

# Context Menus

Plugins may extend existing context menus.

Examples include:

* Station actions
* Playlist actions
* History entries
* Favorites

Context menu entries should only appear when they are relevant.

---

# Notifications

Plugins may notify users through the application's notification system.

Example:

```javascript
context.notifications.show({

    title: "Discord",

    message: "Connected successfully."

});
```

Notifications should be informative without becoming intrusive.

---

# React Components

WebRadio uses React for its user interface.

Plugins may provide React components that are rendered by the Plugin UI system.

Example:

```text
pages/

└── Dashboard.jsx
```

React components should remain self-contained and avoid direct access to internal application state.

---

# Icons

Plugins may include their own icons.

Example:

```text
assets/

└── icons/

    └── discord.svg
```

Icons should follow the application's visual style whenever possible.

---

# Design Principles

## Native Integration

Plugin pages should feel like a natural part of WebRadio.

---

## Consistency

Plugin interfaces should follow the same design language as the core application.

---

## Isolation

A plugin's UI should remain independent from other plugins.

---

## Extensibility

The UI system is designed to grow without requiring changes to existing plugins.

---

# Best Practices

✔ Keep interfaces clean and intuitive.

✔ Reuse shared UI components where available.

✔ Avoid excessive animations.

✔ Support both light and dark themes.

✔ Keep pages responsive.

✔ Use meaningful icons.

✔ Group related settings together.

---

# Common Mistakes

Common UI issues include:

* Overcrowded interfaces.
* Inconsistent layouts.
* Large monolithic components.
* Blocking the UI with long-running tasks.
* Ignoring theme compatibility.

A good plugin should feel indistinguishable from the built-in features of WebRadio.

---

# Future Improvements

Future SDK versions may introduce:

* Widget support
* Dashboard panels
* Dockable windows
* Custom title bar actions
* Dynamic menus
* Layout extensions
* Theme-aware UI helpers

The UI API is designed to evolve while maintaining backwards compatibility.
